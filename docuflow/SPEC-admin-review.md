# Pemeriksaan admin sebelum persetujuan

- Formulir dokumen menampilkan nama kategori, sementara ID/kode kategori dan aturan otorisasi tetap digunakan secara internal.
- Pembuatan Excel membuka editor. Pembuat dapat menyimpan draft atau memilih Submit ke Admin; perubahan yang belum disimpan disimpan terlebih dahulu. Kegagalan penyimpanan tidak mengirim draft.
- Permintaan baru dan draft lama yang belum dikirim memakai tahap `admin_review`. Admin dapat melihat, mengedit dan menyimpan workbook. Pembuat dapat memperbaiki dokumen yang dikembalikan approver lalu mengirim ulang. Riwayat permintaan tetap disimpan secara internal.
- Menu Create / Revise bagi admin memiliki tab Permintaan Masuk dan Dokumen Saya. Klik judul membuka detail; aksi tabel berfokus pada Excel. Admin dapat melanjutkan ke approval dari editor setelah perubahan tersimpan.
- Admin wajib mengisi nomor dokumen saat pemeriksaan, melalui Edit Informasi atau sebelum mengirim persetujuan. Nomor tidak boleh bertabrakan dengan dokumen atau permintaan lain; revisi dapat mempertahankan nomor dokumen sumber.
- Untuk permintaan Excel, admin mengunggah PDF hasil ekspor dari Excel, maksimum 5 MiB, dan memilih setidaknya satu approver. Tidak ada konversi PDF otomatis; admin memeriksa kesesuaian PDF dengan Excel. PDF diverifikasi ekstensi, ukuran dan header, lalu disimpan sebagai file di IndexedDB. Pengajuan yang gagal membersihkan file sementara.
- Approver dipilih satu per satu melalui dropdown pengguna terdaftar, termasuk pembuat dan admin pengirim; pilihan ditampilkan secara ringkas dan dapat dihapus atau ditambahkan kembali. Penugasan memberikan approver akses baca untuk permintaan dan putaran yang ditugaskan meskipun departemennya belum memiliki akses kategori; akses ini tidak berlaku untuk permintaan lain atau dokumen resmi. Tanpa izin kategori, akses penugasan berakhir ketika permintaan ditarik atau dikembalikan untuk diedit.
- Approver mengunggah gambar tanda tangan di profil. Tombol Approval pada tabel menampilkan PDF, dan tombol mengambang memungkinkan memilih tanda tangan serta mengklik posisi pada halaman. PDF bertanda tangan disimpan terpisah dari PDF asli dan diteruskan kepada approver berikutnya; jika dokumen berubah saat terbuka, approver harus membuka kembali. PDF hasil penerbitan berisi tanda tangan semua approver yang membubuhkannya. Data tetap pada browser yang sama dan gambar bukan tanda tangan digital berbasis sertifikat.
- Saat dikirim ke approval, identitas workbook dan PDF beserta versi isi dan metadata dibekukan. Approver melihat PDF final; penerbitan mensyaratkan semua persetujuan pada versi yang sama. View dan unduhan dokumen terbit mengutamakan PDF; workbook tetap tersedia untuk revisi. Referensi file pada riwayat dan dokumen resmi mencegah penghapusan file yang masih digunakan.
- Data tetap berada pada browser/origin yang sama. Pengiriman antar perangkat membutuhkan layanan penyimpanan bersama dan autentikasi server; prototipe lokal belum menyediakan sinkronisasi tersebut.

Verifikasi: `npm run check`, `npm test`, `tests/browser-admin-review-flow.py`, `tests/browser-request-menu.py`, `tests/browser-request-pdf.py`, serta tes browser editor yang relevan. Pengujian alur mencakup simpan otomatis sebelum submit, edit admin, pengembalian dan submit ulang, PDF lebih dari 2 MiB, file tidak valid/terlalu besar, kegagalan submit tanpa meninggalkan file, preview, persetujuan dan unduhan PDF final.
